# ラブコメ波動方程式（RCWE）

> [英語原本](README.md)の参考訳。仕様・判定・ハッシュの正本は英語原本と既存の実行ファイルであり、訳によって変更しない。

RCWEは、架空の二者が時間の中で相互作用を４チャネルへどう配分するかを扱う、反証可能な研究計画である。

\[
\mathbf p=(p_D,p_S,p_C,p_P),\qquad \sum_k p_k=1.
\]

- `D`：その二者に固有の、直接的な恋愛・親密さに関わる相互作用
- `S`：通常の社会的相互作用
- `C`：対立・ライバル関係
- `P`：共同作業・遊び・共創

作業上の標語は **Love is DC; Rom-Com is AC**。好意そのものが振動すると主張するのではない。恋愛的緊張を、知覚された好意だけよりも、相互作用チャネルの配分変化でよく予測できるかを問う。

## 凍結の規律

失敗した検証を救済するためにv2.0を変えない。失敗は`registry/FAIL_LOG.md`、修正候補は`registry/V2.1_CANDIDATES.md`へ記録する。`v2.0-freeze`は作成しない。将来の`v2.0-spec-freeze`は、レビュー、スコアリングの参照実装、合成回復の検証後に限る。これは仕様の凍結を示し、検証完了を意味しない。

回復の受入判定は現在`NOT_ASSESSED`であり、合格ではない。[数値受入計画](docs/NUMERICAL_RECOVERY_ACCEPTANCE_PLAN_v0.1.ja.md)を参照。露出済み40件は監査専用で、閾値開発には使わない。元のベンチマーク成果物は変更しない。再実行は新規出力先に保存する。パッケージの厳密な固定だけでは、プラットフォーム間の分類再現性は保証できない。

別コミット`67c4fc0`で提供されたLinux再現成果物を、コミット済みWindows runと比較した。同一Linuxホストでは固定版・旧版ライブラリの数値fitは一致したが、どちらもWindowsに対して過去の収束フラグが`10/40`反転した。これは回顧的な監査結果であり、受入根拠でも新しい較正ブロックでもない。
