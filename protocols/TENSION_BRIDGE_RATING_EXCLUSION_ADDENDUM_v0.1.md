# Tension Bridge rating-exclusion addendum v0.1

This addendum amends `TENSION_BRIDGE_EXPERIMENT_v1.0.md` before any confirmatory human rating has been collected. The original file remains unchanged for audit. The reference confirmatory runner binds this addendum's SHA-256 in its output.

The confirmatory rating CSV has no analyst-controlled `valid_primary` or `valid_pilot` column. All submitted answers are retained. Primary eligibility is computed from the frozen exposure answers (`prior_exposure`, `knows_future`, `exposure_uncertain`), the offset-aware eligibility/endpoint/rating/next-opening timestamps, and the existing role and reliability gates. There is no free-form, row-level validity switch. A technical invalidation not described by these fields cannot be silently encoded as an excluded row: it needs a prospective, separately versioned reason-code protocol and an independently timestamped source record before confirmatory activation.

This removes the manual exclusion switch but does not prove that every answer generated by a rating system was submitted. Before confirmatory recruitment, the operator must also freeze an exact roster and a source-export commitment procedure analogous to pilot v0.4. Until that provenance path is implemented and externally verifiable, the reference runner emits `CONFIRMATORY_SOURCE_PROVENANCE_PENDING` after an otherwise passing pilot and does not fit confirmatory models. This addendum does not by itself make the study ready for human data collection.
