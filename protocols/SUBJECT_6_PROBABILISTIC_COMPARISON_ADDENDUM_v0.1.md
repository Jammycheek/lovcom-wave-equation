# Subject 6 Probabilistic Model Comparison Addendum v0.1

## Status and scope

This addendum freezes the secondary `M_A`/`M_B` probabilistic comparison for Subject 6. It does not modify the preregistered `KM`, `KT`, `KB`, persona, or H-endogeneity tests; validate Minimal RCWE parameters; implement the full four-channel model; or activate `M_C`.

The question is strictly whether adding a genuinely exogenous shared-event exposure to a pair's own observed Direction history improves prediction of the pair's next qualified IE.

## Target and qualified IEs

The scored target is blind-adjudicated `R_dir` with fixed category order:

```text
[-1, 0, +1, mixed]
```

These denote withdrawal, neutral/maintenance, approach, and mixed. `mixed` is retained as the fourth category and may not be removed after outcomes are known.

A qualified IE is a direct dyadic interaction between Kotaro and the named `KM`, `KT`, or `KB` counterpart under `SUBJECT_6_ASOBI_PROSPECTIVE_v1.0.md` and the Codebook. Pair-external observations do not count as IEs, but an eligible event may form exposure for the next qualified IE. If categorical Direction reliability is below the Codebook gate `kappa >= 0.70`, the comparison is not performed and its status is `MEASUREMENT_FAILURE`.

The confirmatory corpus is the first 10 qualified IEs for each pair, capped at 30 rows. Complete qualified-IE coding for Volume 5 must be declared and committed before scoring, so the corpus cannot stop when a favorable score appears. If a pair has fewer than 10 qualified IEs after complete coding, retain all available rows and report the ordinary activation result; never substitute later volumes or selected highlights.

## Shared-event exposure

For each target IE `n`, freeze `X_shared,n in {0,1}` before revealing its Direction. It is one exactly when at least one eligible event occurred after the preceding qualified IE for that pair ended and before the target IE began.

Exposure and outcome live in separate committed files. Each exposure row records an offset-aware freeze timestamp and exposure-freeze commit; each outcome row records a later reveal timestamp and a distinct outcome commit. The runner rejects rows whose exposure was not frozen strictly before outcome reveal and joins the files only after validating an exact IE-ID match.

An eligible genuinely exogenous shared event must:

- be an explicit event capable of supplying common context to at least two of `KM`, `KT`, and `KB`;
- not have been generated by the preceding change of the target pair; and
- already be observable before the target IE starts.

Events first occurring or becoming known inside a target IE cannot predict that IE; they may become exposure for the next qualified IE. An endogenous-H event—pair change, H observation, then H-designed intervention—cannot alone set `X_shared=1`. A separate eligible exogenous event in the same interval may do so on its own evidence.

The linked event table must support:

`event_id, event_order, event_type, shared_candidate, h_endogenous, eligible_exogenous_shared, source_locator, coder_id, coding_date, future_blind, theory_blind, adjudicated`

The table stores locators, metadata, and short original summaries only; it does not store copyrighted source content.

## Chronology and no leakage

Order all Vol.5 qualified IEs by in-work global chronology. For each row the immutable operation order is:

```text
predict -> record probability -> reveal R_dir -> score -> update
```

Use source-defined order when multiple IEs share a scene. If the source does not determine a unique order, do not break the tie analytically; report a specification problem and stop confirmatory scoring. Duplicate `global_order` values are therefore rejected.

Vol.1–4 summaries are not fitting data. Both models cold-start at the beginning of Vol.5 with `alpha=1` in all four categories for all pairs and, for `M_B`, both exposure strata.

## Model M_A: pair history only

Let `N_A[i,k]` be the number of prior observed outcomes in category `k` for pair `i`. Before target `n`:

\[
P_A(R_n=k\mid i)=\frac{N_A[i,k]+1}{N_A[i,*]+4}.
\]

Only the observed category for the same pair is incremented, and only after that row has been predicted and scored. Prior and observed counts are not double-added.

## Model M_B: pair history by exposure

Let `N_B[i,x,k]` be the prior observed count for pair `i`, exposure `x`, and category `k`:

\[
P_B(R_n=k\mid i,x)=\frac{N_B[i,x,k]+1}{N_B[i,x,*]+4}.
\]

After scoring, only the matching pair/exposure stratum is updated. There is no fallback, backoff, hierarchy, or smoothing beyond the fixed Dirichlet prior. The resulting cold-start penalty is intentional: prequential performance must pay for the additional context split.

## Prequential log score

Use natural logarithms:

\[
LS_{A,n}=\log P_A(R_n),\qquad LS_{B,n}=\log P_B(R_n),
\]

\[
LS_A=\sum_n LS_{A,n},\qquad LS_B=\sum_n LS_{B,n},\qquad
\Delta LS=LS_B-LS_A.
\]

When the activation gate passes, the pooled verdict is:

- `Delta LS >= 2`: `PRACTICAL_SUPPORT_M_B`;
- `-2 < Delta LS < 2`: `INDETERMINATE`;
- `Delta LS <= -2`: `PRACTICAL_SUPPORT_M_A`.

Report pooled totals, each of `KM`, `KT`, and `KB`, mean log score per IE, and a per-IE probability table. Pair scores are diagnostic and are never converted into a vote or combined win/loss total.

## Activation gate

A support verdict is permitted only when all conditions hold:

- at least 12 total scored qualified IEs;
- at least four rows with `X_shared=1`;
- at least four rows with `X_shared=0`; and
- at least two of the three pairs each contain one or more rows in both exposure strata.

Otherwise status is `INSUFFICIENT_SHARED_EVENT_EXPOSURE`. Scores remain descriptive and the thresholds may not be changed after seeing them.

## Separation from primary tests and M_C

This is a secondary empirical test. Its result never overwrites any primary Subject 6 prediction. Support for `M_B` is not proof of Network RCWE; support for `M_A` is not a failure of Minimal RCWE. `M_C` remains unimplemented and may only be considered under the candidate conditions already frozen in the parent protocol. A poor A/B result alone cannot activate it.

## Confirmatory input schema

Three files are required:

- exposure file: `global_order, pair_ie_order, ie_id, pair, x_shared, source_locator, shared_event_adjudicated, exposure_frozen_at, exposure_commit`;
- outcome file: `ie_id, r_dir, direction_coder_a, direction_coder_b, direction_adjudicated, outcome_revealed_at, outcome_commit`;
- manifest: `work_id, version_id, edition, volume, qualified_ie_coding_complete, exposure_freeze_commit, outcome_commit, notes`.

`pair` is one of `KM`, `KT`, or `KB`; `r_dir` and both raw direction codes are one of `-1`, `0`, `+1`, or `mixed`; and `x_shared` is zero or one. `pair_ie_order` is contiguous from 1 and cannot exceed 10. Both adjudication fields must be explicit true values. The scorer rejects invalid categories, pairs, duplicate ordering, non-adjudicated rows, mismatched commits, incomplete corpus declarations, and outcome-before-freeze chronology. Direction reliability Cohen's kappa is computed from the two raw coder columns; it cannot be supplied on the command line.

## Reproducible output

The reference runner writes configuration, all three input SHA-256 hashes, per-IE predictions, pooled and pair summaries, activation status, software and Git provenance, and warnings. Header-only templates return `NO_DATA`; non-identifiable raw reliability returns `DIRECTION_RELIABILITY_NOT_IDENTIFIABLE`; and computed `kappa < 0.70` returns `MEASUREMENT_FAILURE`. None of these states is represented as an A/B verdict.
